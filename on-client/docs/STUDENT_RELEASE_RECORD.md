## 5. 데이터 보존·백업·복원 계획

### 이번에 확인한 보존 상태

- 원본 저장소 HEAD는 기준 21단계 커밋이며, 작업 트리에는 기존 미추적 파일 `student/extension.mjs.backup-step19`와 `student/extension.mjs.backup-step20`이 있었습니다. 두 파일은 원본에 그대로 두었습니다.
- 이 두 백업은 미추적 로컬 파일이므로 21단계 Git 커밋이나 새 복제본의 재현 산출물로 간주하지 않습니다. 복제본으로 복사하지 않았습니다.
- 복제본에서는 Git 상태가 깨끗한 것을 확인했고, 검증 중 코드·설정·인증 파일을 복사하거나 수정하지 않았습니다.
- 백업 파일의 복원, 백업에서의 실행, 실제 사용자 데이터 백업/복구는 수행하지 않았습니다.

### 다음 작업을 위한 계획

1. 변경 전 원본 저장소의 현재 HEAD와 `git status`를 기록하고, 추적 파일 변경과 미추적 백업을 각각 식별합니다.
2. `student/extension.mjs`와 기존 `student/extension.mjs.backup-step19`, `student/extension.mjs.backup-step20`은 서로 다른 역할의 파일로 보존합니다. 백업을 템플릿으로 덮거나 복제본으로 옮기지 않습니다.
3. 복구가 필요하면 먼저 후보 원본을 비교하고 사용자 확인을 받은 뒤 필요한 파일만 복원합니다. 제공 파일 업데이트의 롤백은 `docs/STARTER_UPDATE.md`의 Git 저장점·diff 검토 원칙을 따르며, 학생 파일이나 무관한 파일까지 되돌리지 않습니다.
